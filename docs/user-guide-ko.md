# Stockly 사용자 안내서

마지막 소스 점검: 2026-08-13

이 안내서는 현재 로컬 고객용 앱을 기준으로 한다. 데이터베이스 migration이나 Edge Function이 아직 운영 환경에 적용되지 않았다면 일부 기능에서 “데이터베이스 업데이트가 필요합니다” 같은 안내가 표시될 수 있다.

## 1. Stockly란?

Stockly는 매장의 재고, 발주, 입고 확인, To do, 인수인계, 프랩과 단체주문을 함께 관리하는 앱이다.

주요 기능:

- 바코드로 상품 검색과 등록
- 창고·매장 재고의 입고, 사용, 이동, 실사
- 부족 품목 추가, 긴급 표시, 발주 컨펌
- 입고 예정·완료 기록
- 날짜별 To do와 인수인계
- 프랩 레시피와 제조·소진·폐기
- 단체주문 일정과 필요 수량 계산
- 직원 초대와 선택 권한 부여

## 2. 계정과 권한

### 운영자(`master`)

서비스 전체 매장과 사용자를 관리하는 전용 계정이다. 고객용 Stockly 앱에서는 매장 기능을 사용할 수 없고 별도 운영 관리자 콘솔을 사용한다.

### 매장 관리자(`store_admin`)

본인 매장의 재고 업무와 설정을 관리한다.

- 직원 이름·삭제 관리와 초대코드 생성
- 직원별 추가 권한 부여
- 프랩 품목, 카테고리, 품목 단위, 발주처 관리
- 메뉴 레시피 관리
- 휴무일과 재고 오버뷰 기준 설정

### 직원(`staff`)

기본 재고 업무를 수행한다.

- 홈, 재고현황, 스캔, 부족재고, 작업로그
- 프랩관리모드와 단체주문 계산
- 개별관리 품목과 To do 확인

관리자가 권한을 부여하면 카테고리 관리, 발주처 관리, 메뉴 레시피 등록, 발주 품목 확정도 사용할 수 있다.

## 3. 로그인과 회원가입

지원 방식:

- 이메일/비밀번호 로그인과 회원가입
- Google
- 카카오
- Apple

이메일 로그인 화면에서는 비밀번호 재설정 메일도 요청할 수 있다. OAuth 사용 가능 여부는 Supabase와 각 제공자 콘솔 설정에 따라 달라진다.

### 처음 가입한 계정의 매장 연결

프로필이 없는 계정은 로그인 뒤 `매장 연결` 화면으로 이동한다.

새 매장을 시작하려면:

1. `새 매장 만들기`에서 매장 이름을 입력한다.
2. 생성하면 해당 매장의 관리자로 시작한다.

기존 매장에 참여하려면:

1. 관리자에게 8자리 초대코드를 받는다.
2. `초대코드로 참여`에 코드를 입력한다.
3. 참여 후 초대한 매장의 직원 또는 관리자로 연결된다.

초대코드에는 이메일 제한이 없다. 이미 매장에 소속된 계정은 다른 매장 초대코드를 사용할 수 없다.

`?inviteCode=ABCD2345` 형식의 링크로 접속하면 앱이 로그인 뒤 사용할 코드를 보관하고 자동 입력한다.

## 4. 기본 화면

하단에는 다섯 메뉴가 있다.

- `홈`: 오늘·내일 업무, 입고, To do, 인수인계
- `재고현황`: 전체 상품의 재고 목록과 오버뷰
- `스캔`: 카메라, 사진 또는 검색으로 상품 찾기
- `부족재고`: 부족·수동 추가·긴급 품목과 발주 확정
- `작업로그`: 기간별 재고 작업 기록

왼쪽 상단 Stockly 메뉴에는 프랩, 단체주문, 개별관리 품목, To do와 관리 기능이 표시된다. 계정 역할과 부여받은 권한에 따라 보이는 메뉴가 다르다.

## 5. 바코드 스캔

1. 하단 `스캔`을 누른다.
2. 앱에서는 native scanner, 웹에서는 카메라 scanner가 시작된다.
3. 등록된 활성 상품이면 `재고 작업`으로 이동한다.
4. 미등록 바코드면 `상품 등록`으로 이동한다.

추가 기능:

- 상품명·기본 바코드·보조 바코드 검색
- 사진에서 바코드 인식
- 웹 스캐너의 카메라 확대
- 12자리/13자리 앞자리 0 차이 보정

`입고여부만 확인` 상품도 스캔 후 재고 작업 화면으로 이동한다.

## 6. 상품 등록과 수정

입력 항목:

- 상품명
- 바코드
- 카테고리
- 보관 구분: 미지정, 냉장, 냉동, 상온의 복수 선택
- 발주처
- 기본 위치: 창고 또는 매장
- 품목 단위
- 최소 재고
- 상품 발주 링크
- 상품당 단위: 무게, 부피 또는 낱개
- 손질 필요 여부와 손질 후 단위
- 입고여부만 확인

상품당 단위는 프랩과 단체주문 계산에 사용한다. `낱개` 기준에서는 손질 후 무게·부피를 입력하지 않는다.

`입고여부만 확인`을 켜면 최소재고가 0으로 고정되고 실제 수량 대신 입고 완료 기록을 남긴다.

등록을 마치면 새 상품의 재고 작업 화면으로 이동한다. 수정 화면에서는 상품 비활성화와 중복 상품 병합도 할 수 있다.

## 7. 재고 작업

일반 상품의 화면 표시는 다음과 같다.

- 창고·매장 현재 수량
- 위치별 마지막 실사 날짜와 작업자
- 총재고와 최소재고
- 작업 선택
- 상태와 메모

내부 기록값 `조정`은 사용자용 화면에서 `실사`로 표시된다. `출고`는 화면에서도 `출고`로 표시된다.

### 실사

선택 위치의 실제 수량으로 맞춘다.

예: 창고의 실제 재고가 10이면 `창고`를 선택하고 `실사`, 수량 `10`을 저장한다.

### 입고

선택 위치의 재고에 입력 수량을 더한다. 입고가 완료되면 해당 상품의 수동 추가·긴급·컨펌 진행 상태가 정리될 수 있다.

### 이동

`창고 → 매장` 또는 `매장 → 창고`를 선택한다. 한쪽 수량을 줄이고 반대쪽을 늘린다.

### 사용

선택 위치의 수량에서 입력 수량을 뺀다. 음수가 되는 작업은 저장할 수 없다.

### 위치와 최소재고

- 창고 또는 매장 카드를 짧게 누르면 위치를 선택한다.
- 길게 누르면 해당 위치를 상품의 기본 위치로 저장한다.
- 총재고 옆 `수정`에서 최소재고를 바로 바꿀 수 있다.

### 상태 기반 관리

상태 기능을 켜면 수량 계산 대신 아래 상태로 부족 여부를 관리한다.

- 충분
- 절반 이하
- 발주 필요

`발주 필요`인 상품은 부족재고에 표시된다.

### 메모

상품별 메모를 저장하고 메모 히스토리를 확인할 수 있다. 본인이 작성한 메모만 수정할 수 있다.

## 8. 입고여부만 확인 상품

이 상품은 창고·매장 수량을 변경하지 않는다.

1. 재고 작업 화면에서 입고 개수를 입력한다.
2. `입고완료`를 누른다.
3. 홈과 작업 로그에 입고 기록이 남는다.
4. 수동 추가·긴급·컨펌 상태가 정리된다.

재고 현황에는 수량 대신 `-` 또는 `확인`으로 표시되지만 발주 링크·문자 버튼은 계속 사용할 수 있다. 재고 현황에 별도의 입고완료 버튼은 없다.

## 9. 작업 히스토리와 되돌리기

재고 작업 상단의 히스토리 버튼에서 과거 작업 뒤 수량을 확인하고 원하는 시점으로 되돌릴 수 있다.

- 현재 상태는 선택할 수 없다.
- 되돌리면 창고와 매장 수량이 해당 시점 값으로 바뀐다.
- `입고여부만 확인` 상품에는 수량 되돌리기를 제공하지 않는다.

작업 전 상품명, 작업 시각, 창고·매장 수량을 확인한다.

## 10. 재고 현황

### 목록

- 카테고리는 기본 한 줄 가로 스크롤이며 화살표로 전체 펼침·접기가 가능하다.
- 상품명 또는 바코드로 검색한다.
- 창고·매장 수량과 발주 버튼을 확인한다.
- 행을 누르면 재고 작업으로 이동한다.

발주처가 링크 방식이면 상품 URL을 열고, 문자 방식이면 수량을 입력해 문자 앱을 연다.

### 오버뷰

상품별 총재고 상태를 카드로 본다.

- 이름순
- 최근 30일 재고 변동 많은 순
- 중요 품목만 표시

관리자는 별표로 중요 품목을 지정할 수 있다. 카드의 부족·주의·넉넉 기준은 환경설정의 매장 공용 배수를 사용한다.

## 11. 부족 재고와 발주

부족재고 표시 대상:

- 총재고가 최소재고 이하인 상품
- 상태가 `발주 필요`인 상품
- `품목추가`로 수동 선택한 상품
- 긴급으로 표시한 상품

`입고여부만 확인` 상품은 자동 수량 부족으로는 표시되지 않지만 수동 추가나 긴급으로 표시할 수 있다.

### 품목추가

1. 상단 `품목추가`를 누른다.
2. 검색어가 없으면 카테고리를 먼저 선택한다.
3. 검색어가 있으면 상품을 바로 확인한다.
4. 발주품목 체크 또는 `긴급` 체크를 선택한다.

긴급 체크를 켜면 해당 품목은 발주품목에도 자동 포함된다. 수동 추가·긴급 품목은 목록에서 `삭제`할 수 있다.

### 컨펌

1. 필요한 상품의 `컨펌` 체크를 켠다.
2. 필요한 경우 `필요 개수`를 입력한다.
3. 권한이 있는 사용자가 상단 `컨펌`을 누른다.
4. 메모를 입력하고 `컨펌하기`를 누른다.

당일 기존 확정 목록은 새로 컨펌한 목록으로 교체된다. `컨펌 완료한 품목 숨기기`를 켜면 진행 중인 확정 품목을 현재 부족 목록에서 숨긴다.

### 발주하기

`발주하기`에서는 날짜별 확정 품목, 메모, 작성자, 필요 개수를 확인한다.

오늘 확정 목록에 한해 권한이 있는 사용자는:

- 품목 추가
- 품목 삭제
- 전체 컨펌 취소

를 할 수 있다. 각 상품의 링크 또는 문자 발주도 이 화면에서 실행할 수 있다.

실제 입고는 상품의 재고 작업 화면에서 처리한다. 과거 문서의 `프레시상품`, 별도 `긴급발주요청`, `입고완료 되돌리기` UI는 현재 사용하지 않는다.

## 12. 홈

홈 상단에서 `오늘`과 `내일`을 전환한다. 휴무일이면 휴무 상태가 표시된다.

### 입고품목

- 오늘: 입고 예정과 실제 입고 완료를 함께 표시
- 내일: 확정 발주를 기준으로 입고 예정 표시
- 캘린더: 날짜별 입고 예정·완료 확인

오늘 입고 기록이나 입고 예정 항목을 삭제할 수 있다. 오늘 입고 기록은 최근 삭제를 되돌릴 수 있다.

### To do list

- 오늘과 내일 할 일을 추가한다.
- 오늘 할 일은 완료 체크할 수 있다.
- 캘린더에서 지정일 할 일을 추가·수정·삭제한다.
- 루틴 또는 자동 재고 확인 To do는 별도 표시된다.

### 인수인계

내일 근무자에게 전달할 내용을 저장하고 날짜별 히스토리를 확인한다.

상단 캘린더 버튼에서는 입고, To do, 인수인계를 묶은 `매장 타임라인`을 확인한다.

## 13. 작업 로그와 개별관리 품목

### 작업 로그

기간별로 입고, 사용, 이동, 실사, 메모, 프랩 관련 기록을 확인한다. 작업 시간, 작업자, 상품, 수량 변화가 표시된다.

### 개별관리 품목

재고 작업에서 상태 기능을 켠 품목만 모아 본다. 과거 메뉴명 `최소재고 품목`과 같은 화면이며 충분, 절반 이하, 발주 필요 상태를 확인한다.

## 14. To do list 관리

상단 메뉴의 `To do list`에서는 홈에 생성할 루틴을 관리한다.

- 지정일
- 일간
- 주간
- 월간
- 임의 간격

루틴의 활성 상태와 일정을 관리하며 홈에서는 해당 날짜의 실제 할 일로 표시된다.

## 15. 프랩

### 프랩품목 관리

관리자는 반제품 레시피, 원재료 사용량, 손실률, 유통기한 사용 여부, 표시 순서를 관리한다.

### 프랩관리모드

직원은 프랩 품목을 선택해 제조, 소진, 폐기를 기록하고 현재 batch와 유통기한을 확인한다.

중량·부피·낱개 단위가 계산에 영향을 주므로 상품당 단위와 레시피 단위를 정확히 입력한다.

## 16. 단체주문

`단체주문 계산`에서는 날짜별 주문 일정을 저장하고 메뉴 수량으로 필요한 원재료를 계산한다.

- 주문 날짜 또는 기간 선택
- 고객 연락처 저장
- 메뉴별 수량 입력
- 필요량과 발주량 결과 확인

`메뉴 레시피 등록` 권한이 있는 사용자는 메뉴와 원재료 사용량을 관리한다. 현재 프랩 재고를 포함한 완전한 자동 발주 계산은 통합 To do의 후속 범위다.

## 17. 기준정보 관리

### 카테고리 관리

카테고리 추가, 이름·순서·활성 상태 관리와 카테고리별 상품 일괄 수정을 지원한다.

### 품목 단위 관리

상품 등록에 사용하는 단위를 추가하고 이름, 순서, 활성 상태를 관리한다. 사용 중인 단위는 바로 삭제할 수 없다.

현재 로컬 변경은 품목 단위를 매장별로 분리하는 migration을 포함한다. 운영 DB가 아직 갱신되지 않았으면 이 화면이 정상 동작하지 않을 수 있다.

### 발주처 관리

발주처는 다음 방식 중 하나를 사용한다.

- 링크 발주
- 문자 발주: 전화번호와 문자 template

상품의 발주처 이름과 상품 URL 설정에 따라 재고 현황·부족재고의 발주 버튼이 동작한다.

## 18. 직원 관리와 권한 부여

매장 관리자는 `직원 관리`에서:

- 직원·관리자 초대코드 생성
- 같은 매장 구성원 확인
- 직원 이름 수정
- 일반 직원 계정 삭제

를 수행한다.

초대코드는 복사해 전달한다. 고객용 직원 관리 화면은 현재 코드만 복사하며 앱 주소를 함께 공유하는 기능은 후속 작업이다.

`권한 부여`에서는 일반 직원에게 다음 권한을 켜거나 끈다.

- 카테고리 관리
- 발주처 관리
- 메뉴 레시피 등록
- 발주 품목 확정

## 19. 환경설정

모든 사용자가 확인하거나 사용할 수 있는 항목:

- 현재 이메일·매장·권한
- 다크모드
- Google·카카오 계정 연동과 해제
- 계정 탈퇴
- 로그아웃

관리자 전용 항목:

- 재고 오버뷰의 넉넉 기준
- 매주 반복 휴무
- 특정 날짜 휴무와 사유

휴무일을 추가하면 미래 To do와 인수인계가 다음 영업일로 이동할 수 있다.

## 20. 계정 탈퇴

현재 로컬 소스의 분기:

- 일반 직원: 본인 계정만 영구 삭제
- 공동 매장 관리자: 같은 매장의 일반 직원을 새 관리자로 이관한 뒤 본인 계정 삭제
- 구성원이 없는 개인 매장 관리자: 30일 복구 기간으로 탈퇴 요청
- 운영자: 고객용 탈퇴 화면에서 처리하지 않음

개인 매장은 30일 안에 같은 계정으로 로그인해 매장과 계정을 복구할 수 있다. 기간 뒤 자동 영구 삭제에는 서버의 purge scheduler가 필요하다.

탈퇴 기능은 Edge Function 배포 상태에 따라 실제 운영 동작이 달라질 수 있으므로 중요한 계정에서는 관리자에게 확인한다.

## 21. 자주 발생하는 상황

### 초대코드가 적용되지 않음

- 이미 다른 매장에 연결된 계정인지 확인한다.
- 코드의 공백을 제거하고 대문자로 다시 입력한다.
- 관리자가 새 코드를 생성하도록 요청한다.

### 상품이 부족재고에 계속 남음

- 실제 총재고가 최소재고 이하인지 확인한다.
- 상태 기능이 `발주 필요`인지 확인한다.
- 수동 추가 또는 긴급 상태인지 확인한다.
- `컨펌 완료한 품목 숨기기` 설정을 확인한다.

### 저장 중 다른 직원이 먼저 변경했다는 메시지

최신 수량이 다시 로드된 뒤 작업 내용을 확인하고 다시 저장한다. 동시에 같은 상품을 수정해 이전 수량을 덮어쓰는 것을 막기 위한 안내다.

### 앱에서 웹 변경이 보이지 않음

Capacitor 앱은 Vercel이 아니라 설치된 로컬 `dist`를 사용한다. 새 TestFlight build 또는 Xcode 재설치가 필요하다.

### 기능에서 DB 업데이트 안내가 표시됨

앱 코드와 운영 Supabase migration 상태가 다를 수 있다. 관리자에게 해당 migration과 Edge Function 배포 여부 확인을 요청한다.
